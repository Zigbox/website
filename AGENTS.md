# zigbox.org: operating instructions

This repository builds `zigbox.org`, served by a Cloudflare Worker with static assets only
(`wrangler.jsonc`, worker `zigbox-org`, custom domain `zigbox.org`). It moved off GitHub Pages
on 2026-11-05 because Pages kept failing to issue the domain's certificate. The deploy needs the
repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`; a pull request only
assembles the site and checks the config.

## Layout

| Path | Comes from |
|---|---|
| `/` and `/errors/` | `src/` in this repository |
| `/errors/box/<code>.html` | `site/errors/` on `Zigbox/zigbox` `main`, generated by `zig build errors-site` there |
| `/errors/cube/<code>.html` | `site/errors/` on `Zigbox/zigcube` `main`, generated the same way there |
| `/zigbox/`, `/zigcube/` | `site/` on each repository's `main` (their project sites), copied at build time |

The decisions are `docs/decisions/2026-11-04-errors-on-org-site.md` in Zigbox and Zigcube.

## Rules

- Never hand-edit an error page. They are generated in their product repository and copied here
  by `.github/workflows/deploy.yml`. Fix the generator there.
- Never add a path under `/zigbox/` or `/zigcube/`: those belong to the project sites, which
  are edited in their own repositories.
- A URL ending in `.html` redirects (307) to the same URL without it (the assets'
  `auto-trailing-slash` handling); links may use either.
- Pages here are plain HTML and CSS, light and dark, readable at phone width.
- The workflow redeploys on a push to `main`, every six hours, on `workflow_dispatch`, and on a
  `repository_dispatch` of type `site`.
- Commits follow the Zigbox repository's rules: squash merges, no model names in messages.
